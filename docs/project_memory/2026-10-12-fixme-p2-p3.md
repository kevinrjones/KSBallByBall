# Close P2s and residual P3s 1–9

### Title

Unify journal recovery, fail closed on provenance errors, and complete residual write/link cleanup

### Date/time completed

2026-10-12 13:00

### What was shipped

- FILE fallback and DIRECTORY publication now use one non-atomic journal phase
  machine; recovery commits only `PUBLISHED` and restores available backups for
  earlier phases. The FILE atomic-move fast path remains journal-free.
- Provenance-query `SQLException`s now propagate. Connection-failure and
  readable-table tests cover fail-closed behavior and normal change detection.
- Folded transactional identity maps, counters, snapshots, commit, and rollback
  directly into `IdentityCore`; JDBC ownership composes core ownership with DB
  rows. JDBC and SQL-script UPDATE generation share one helper, and
  `setJdbcValue` lives beside `JdbcRowSink`.
- Write/link APIs now carry `SourceCaId`; parser link results map directly to
  parse failures, and the JDBC alias repository implements the resolver API.
- Added MariaDB 11.4 and PostgreSQL 17 Testcontainers tests that apply generated
  schema scripts and verify usable tables/indexes, unique aliases, and alias
  preservation on reapplication.
- Updated `docs/FIXME.md`, the database architecture map, README, ADR 0047, and
  added ADR 0048 for the recovery policy.

### Key decisions

- `PUBLISHED` is the only durable commit marker. Earlier journal phases restore
  an available backup; if none exists, restart recovery preserves a possibly
  moved target because the journal cannot prove what happened.
- Preflight recovery during a new replacement retains that call's supplied
  source while restoring old state, then proceeds with the requested write.
- `Info.sourceCaId` remains `String?` on the wire; `Database` validates it once
  into `SourceCaId`, and write/link repository boundaries use the tiny type.
- P3-10 remains out of scope and deferred.

### Gotchas

- MariaDB/PostgreSQL generated-schema application requires working Docker; the
  two generated-DDL container tests ran successfully. The separate optional
  MariaDB stats integration test remains independently skippable.
- `koverHtmlReport` is not configured for `bbb-update-database` or
  `bbb-parse-cricsheet`; a coverage percentage could not be produced for these
  modules. Kover is currently applied to `bbb-shared` only.
- No-backup recovery intentionally leaves an existing target untouched; active
  in-process rollback has stronger cleanup when a new target was created.
